# 独立下载后端

`download-server.py` 仅监听 `127.0.0.1`，为既有 IIS 下载入口提供静态文件。默认上游端口为 9136；不改变 IIS 9134 转发规则、Portal 9135 或公开下载 URL。它不依赖旧 Prompts 进程、Codex、插件缓存或发布审计工具。

只允许 GET/HEAD 读取既有公开目录：`/downloads/` 下的 ZIP、清单、校验文本和发布历史，以及 `/project-delivery-hub/`、`/assets/` 的静态页面资源。根地址仍跳转到 `/project-delivery-hub/`。目录浏览、隐藏文件、隔离候选、路径越界、链接和 EFS 路径均拒绝；所有旧 `/api/` 路径均不可用。此恢复不恢复旧 Prompts 编辑功能。文件不存在为 404，读取异常为 503，不将暂时故障伪装成无下载包。

下载后端不创建、修改、激活或重新打包任何 ZIP；未发布或被隔离的候选仍需按插件发布流程重新校验并人工确认。公开文件只能由可信的本机发布过程维护，不得把私有配置、日志或程序文件放入共享目录。

## 候选验证

把 `start-downloads.ps1`、`portal-supervisor.ps1` 和 `download-server.py` 复制到独立、固定的运行目录；不要从开发工作树、插件缓存或临时工具路径长期启动。根据 `download-config.example.json` 准备独立配置，固定 Python、服务脚本和监督脚本的路径与 SHA-256。配置和日志须位于公开共享目录之外，日志目录须预先存在。

```powershell
# 默认只核对配置/文件摘要，并在独立 Python 进程验证共享目录，不启动服务。
.\start-downloads.ps1 -ConfigPath C:\PortalDownloads\config.json -ConfigSha256 <配置摘要>
```

隔离功能测试使用临时共享目录及 49152–65535 中未占用的本机端口。增加 `-Run -ProbeSeconds 10` 后才会启动；就绪检查核对 PID、启动时间、程序路径、父进程、命令标记、页面字节及 404 边界，探测期满自动清理自有子进程。普通持续运行仅增加 `-Run`。配置固定总重启预算；每次恢复重验依赖，不接管或关闭未知监听。

```powershell
python -B -m unittest discover -s tests -p test_download_server.py -v
python -B -m unittest discover -s tests -p test_persistent_launcher.py -v
```

## 持久生效与回滚

脚本不注册计划任务、不修改 IIS、防火墙或证书。经授权维护时：

1. 回读现有任务和 IIS 转发配置，确认端口归属。将原始配置及任务定义保存到非交付恢复目录，逐项校验摘要；任务原先不存在时明确记录不存在。
2. 写入固定候选，回读摘要并运行隔离测试，再注册禁用的候选任务。任务使用当前用户交互式登录、最低权限、隐藏窗口，不依赖 Python/Codex 的 PATH。回读动作和触发器后，从独立进程执行仅验证模式。
3. 候选、恢复副本及恢复命令全部通过后，启用并启动。验证仅本机上游监听，再从 9134 和 Portal 9135 回读实际 ZIP，并与原始文件 SHA-256 比对，同时检查缺包和隔离文件的 404。
4. 任一步失败立即停止，不继续激活；仅清理经 PID、启动时间、路径和命令核实的本次进程，恢复原任务定义（或删除本次新建任务），重新回读离线/原状态。IIS 与发布文件始终不变。

登录触发的计划任务保证用户登录后常驻，不代表未登录时运行。不得通过此恢复自动提权、扩大监听范围、启用旧管理 API 或绕过发布审计。
