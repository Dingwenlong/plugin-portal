# Portal 跨网段完整管理设计

日期：2026-08-31

状态：聊天设计已确认，书面规格待复核

## 目标

让通过 `https://192.168.7.125:9135` 访问 Portal 的设备能够完成与本机管理页相同的资料操作，并让依赖文件选择的功能在远端浏览器中真正可用，而不是只显示按钮。

本次开放以下能力：

- 纳入、刷新和回滚插件公开快照。
- 新增、编辑和删除 Prompt。
- 配置和保存流程。
- 上传候选 ZIP，经 Plugin Release 审计后发布到现有 9134 下载目录。

9135 不增加登录、来源网段白名单或用户角色。任何能够访问该 HTTPS 地址的设备都拥有上述管理能力。网络可达性是唯一外部访问边界。

## 第一性原理与取舍

Portal 需要的是插件的公开投影，不是服务器文件系统路径，也不是执行或安装插件。远端浏览器无法操作服务器桌面的目录或文件选择器，因此不能通过解除 `readOnly` 假装实现远端管理。

采用浏览器上传 ZIP：

- 纳入插件时上传插件 ZIP，服务器只读取生成公开快照所需的内容。
- 发布下载时上传目标插件自身发布流程产生的候选 ZIP，服务器继续委托 Plugin Release 审计。
- 不接受浏览器提交任意服务器路径、UNC 路径或共享盘路径。
- 不扫描网段、插件市场或服务器目录，不自动安装插件，不执行上传内容。

未采用的方案：

- 只列出服务器已安装插件：改动较小，但不能纳入远端设备持有且服务器尚未安装的插件，不满足“不做添加限制”。
- 开放服务器路径或 SMB 路径：会暴露主机文件系统边界，且跨网段身份和可达性不稳定。

## 访问模式

服务器保留三种明确模式：

| 模式 | 正式入口 | 写入 | 文件来源 |
| --- | --- | --- | --- |
| `local-management` | `127.0.0.1:9137` | 允许 | 服务器本机选择器 |
| `remote-management` | HTTPS 代理后的 `192.168.7.125:9135` | 允许 | 浏览器 ZIP 上传 |
| `read-only` | 测试或明确只读部署 | 拒绝 | 无 |

`GET /api/access` 返回 `readOnly` 与 `fileSelectionMode`。`fileSelectionMode` 只允许 `server-picker`、`browser-upload` 或 `none`。前端根据能力选择文件交互，但所有写权限仍由后端模式判定，不能仅靠隐藏按钮控制。

CLI 新增与 `--read-only` 互斥的 `--remote-management`。正式远端管理后台必须绑定 `127.0.0.1:9135`，同时提供严格匹配的 `--https-origin https://<私有IPv4>:9135`；不允许直接监听 `0.0.0.0`、公网地址或非 9135 端口。9137 的现有本机模式保持不变。

## 组件边界

### 浏览器上传客户端

远端模式下，插件管理和下载发布对话框使用 `<input type="file" accept=".zip,application/zip">`。选择文件后立即显示文件名和大小，上传期间禁用重复提交，并保留可访问名称、错误反馈和焦点恢复。

本机模式继续使用现有 Windows 目录或 ZIP 选择器。两种模式在生成候选以后共用同一套预览、确认、revision 和结果界面。

### 上传暂存库

新增独立的进程内上传暂存库，职责仅为：

- 将请求体流式写入 OS 私有临时目录，不把整个 ZIP 常驻内存。
- 每个会话最多保留一个插件导入上传和一个下载发布上传。
- 上传替换、取消、确认成功、上传或安全验证失败、15 分钟过期或服务器关闭时清理文件和解压目录。
- 全局最多保留 16 个活动上传；达到上限时返回明确的繁忙错误，而不是继续占用磁盘。
- 公共响应只返回不可猜测的 `uploadId`、文件名和字节数，不返回服务器路径。

清理使用请求触发的过期回收，并在服务器关闭时执行最终回收；不增加常驻轮询线程。

### ZIP 安全读取

插件导入 ZIP 在私有临时目录安全解压。验证规则包括：

- 压缩文件不超过 128 MiB。
- 最多 4096 个条目，总解压大小不超过 256 MiB，单条目不超过 32 MiB。
- 拒绝加密条目、绝对路径、`..`、反斜线混淆、空路径段、链接、reparse/symlink 表示、重复规范路径和不区分大小写冲突。
- 拒绝超过 100:1 的异常压缩比例及不受支持的压缩方式。
- ZIP 中必须且只能解析出一个包含 `.codex-plugin/plugin.json` 的插件根目录；允许文件位于 ZIP 根或单一顶层目录。

安全解压后继续调用现有公开投影读取器；不得导入 Python/JavaScript 模块、启动 MCP、运行脚本或安装插件。

下载发布 ZIP 不解压供 Portal 使用，只流式暂存并交给现有 Plugin Release 审计器。既有 128 MiB、身份、版本、哈希、文件集合和 9134 回读门禁保持不变。

### 快照图标资产

远端纳入的插件可能未安装在服务器缓存中，因此图标不能继续只依赖已安装插件目录。

生成导入候选时同步读取允许类型和大小范围内的公开图标。确认纳入时，以 `pluginKey + snapshotId` 为键原子保存不可变图标资产；活动快照切换或回滚时自动读取对应资产。旧快照没有持久图标时，继续回退到精确版本的已安装缓存，再回退通用图标。

图标 URL 继续绑定 catalog revision，纳入、刷新或回滚完成后的目录重读会自然失效浏览器缓存，无需整页刷新。

## API 与资料流

### 插件纳入

1. 浏览器建立现有管理会话。
2. `POST /api/uploads/plugin-import` 以 `application/zip` 流式上传，携带会话令牌和标准 `Content-Disposition` 文件名。
3. 后端完成大小与 ZIP 结构检查，返回会话作用域的 `uploadId`。
4. `POST /api/plugins/import/preview` 使用统一的来源联合结构：本机为 `server-directory`，远端为 `upload`，其余 target、规范路径和扩展工具字段保持原语义。
5. 后端生成并冻结快照与图标候选；公开响应不含路径。
6. 现有 promote 请求以 `candidateId + expectedRevision` 确认。成功后写入快照、图标资产和 catalog，再清理上传。

候选创建成功后立即清理上传 ZIP 与解压目录，确认前只使用冻结的快照和图标资料。公开投影预览失败时保留已通过 ZIP 安全验证的上传，直至同会话重试、替换、取消或过期，以便修正规范路径等可选字段。

### 下载发布

1. 浏览器在已纳入插件条目选择候选 ZIP。
2. `POST /api/plugins/{pluginKey}/download-publication/upload` 流式上传并建立会话候选。
3. 后端绑定当前活动插件版本，调用 Plugin Release 审计并返回现有公开预览字段。
4. 现有 confirm 请求发布同一不可变暂存文件；确认前再次核对文件身份和哈希。
5. 成功后原子写入 9134 下载目录、执行 HTTP 回读、写回执并清理暂存文件。

确认、替换、过期或会话隔离都不能跨 pluginKey、版本或浏览器会话复用候选。

## HTTP 与代理边界

9135 的 Caddy 移除当前“非 GET/HEAD 直接 403”规则，将请求原样代理到 loopback Python 后台。Caddy 继续：

- 只绑定明确的 `192.168.7.125:9135`。
- 使用现有内部 CA 和 HTTPS。
- 关闭管理端口、持久动态配置和自动 HTTP 跳转。
- 保留原始 Host 与 Origin，不信任客户端转发头来决定权限。

Python 后台对全部 API 请求验证准确 Host；有 Origin 时必须精确等于配置的 HTTPS origin。管理会话、不可猜测候选 ID、revision 和插件身份校验继续生效。

`remote-management` 与 `read-only` 一样只从启动时冻结的 `index.html` 和 `assets/` 白名单提供静态文件；开放写 API 不意味着允许远端读取运行目录中的其他文件。`local-management` 保持现有本机静态文件行为。

本设计不增加身份验证、IP 白名单或速率账户。文档必须明确：任何可路由至该地址且信任证书的设备都可以修改 Portal 资料和发起经审计的下载发布。

## 错误处理

新增错误保持结构化 JSON，不泄露本机路径：

- `payload_too_large`：压缩请求超过 128 MiB。
- `upload_busy`：活动上传达到全局上限。
- `upload_not_found`：uploadId 不存在、过期或属于其他会话。
- `archive_invalid`：ZIP 格式、条目或插件根结构不合法。
- `archive_unsafe`：路径、链接、大小、压缩比例或冲突检查失败。
- `plugin_preview_failed`：现有公开投影验证失败。
- `revision_conflict`：目录、Prompt 或流程并发修改。
- 现有 Plugin Release 与下载发布错误码保持不变。

上传中断只删除未完成临时文件，不建立候选。任何失败都不能保留 `.partial`、解压残留或公开半成品。

## 前端行为

- `readOnly=false` 时显示 Hub 纳入、下载发布、Prompt 和流程全部操作。
- 远端模式不显示或调用服务器文件选择器；文件按钮直接打开浏览器选择器。
- 本机模式的既有选择器行为不变。
- 上传、审计和保存期间显示明确状态并禁止重复提交；失败后允许重试。
- 成功纳入、刷新或回滚后重读 catalog 与活动快照，图标、版本和页面内容立即更新，不执行整页 reload。
- 主题、滚动位置、弹窗焦点恢复和胶囊显隐规则保持不变。

## 发布与恢复

本批实现阶段不操作现场 9134、9135、9137 或 9136。

后续得到明确发布授权后采用两阶段生效：

1. 在非生效目录构建候选，使用临时后台端口和临时 Caddy 端口验证 HTTPS、全部写流程、静态哈希、插件资料和恢复构建。
2. 回读并保存当前 9135 Python/Caddy 精确进程、命令行、配置、首页哈希和构建目录；验证候选配置可独立启动。
3. 只停止精确匹配的旧 9135 Portal 与 Caddy 进程，原子切换构建和配置，再启动新进程。
4. 回读 GET/HEAD、`/api/access`、实际写入流程、插件数据、下载服务和进程身份。
5. 任一步骤失败时停止新进程，恢复旧 Caddy 配置和旧构建，重新验证只读旧站可用。

9134 只接受经确认的下载发布文件，不重启；9136 始终不操作。

## 非目标

- 不增加用户、登录、权限角色、审计账户或网段 ACL。
- 不安装、升级、启用或执行上传插件。
- 不生成目标插件发布候选，不替代目标插件自身发布流程。
- 不扫描网络、服务器插件目录或在线市场。
- 不修改插件公开快照、Prompt 或流程的业务数据结构。
- 不改变封面、Header、主题、路由或服务器 API 之外的视觉设计。
