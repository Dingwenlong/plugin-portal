# Plugin Portal 旧版资料迁移与插件站点收敛设计

日期：2026-08-26

状态：用户已确认

## 1. 目标

将研发助手旧 Portal 中仍由用户使用的资料一次性迁入独立 Plugin Portal，并把插件站点收敛为单插件阅读空间：插件管理只存在于 Hub；进入某个插件后不再显示插件切换器或管理入口。

迁移完成后，Plugin Portal 不依赖旧 Portal 服务。研发助手插件、昱勝 Inc 与 Plugin Portal 的源码、版本和本地资料继续相互隔离。

## 2. 插件站点导航

- `/#/hub` 保留插件目录与“纳入插件”入口。
- `/#/plugins/<pluginId>/...` 只展示当前插件。
- 侧栏品牌位置显示当前插件名称，点击后进入该插件鸟瞰全景。
- 侧栏菜单不显示“鸟瞰全景”；Skills、Prompts、MCP、扩展工具、工程规范、版本沿革继续保留。
- 插件站点不显示插件下拉选择器、插件技术 ID 或“管理插件”按钮。
- 浏览另一个插件必须先返回 Hub，再从插件目录进入，避免把管理与阅读混在一起。

## 3. Prompt 资料与交互

Prompt 使用旧版公开语义：

```json
{
  "id": "prompt-1",
  "scenario": "我自主规划，AI完成后",
  "content": "关于当前情况，我最大的遗漏是什么？",
  "createdAt": "2026-08-12T07:38:30.798Z"
}
```

- 列表显示“常用场景、Prompt、添加时间、操作”。
- 新增与编辑使用模态框，字段为“常用场景”和“Prompt 内容”。
- 新增时由服务端或前端生成当前 UTC 时间；编辑保留原添加时间。
- 模态框支持关闭按钮、取消、保存、Escape、焦点进入和关闭后焦点恢复。
- Prompt 仍按完整 `target/pluginId` 隔离。

旧 `{title, content}` 结构不是正式兼容输入；本次迁移与模型升级在同一版本原子完成，避免长期双读。

## 4. 鸟瞰全景配置

配置流程使用模态框，数据模型仍为既有 `Tab -> 流程区域 -> 步骤` 与显式 `next` 图关系，不增加第二套格式。

编辑器改为三级级联：

1. 左列选择和管理 Tab。
2. 中列只显示当前 Tab 的流程区域。
3. 右列只显示当前流程区域的步骤，并编辑角标、标题、说明与后续步骤。

同一时间只编辑一条层级路径。新增、删除、排序、预览和图结构校验继续保留；保存前仍拒绝未知连接、重复 ID、循环、多个入口和不可达步骤。

## 5. 一次性迁移

新增显式迁移命令，从用户指定的旧 Portal 基址读取资料。命令分为预览和应用两个阶段：

```text
python -m plugin_portal migrate-legacy --source-url http://127.0.0.1:9136/project-delivery-hub --plugin-key company-dev/project-delivery-hub --data-root <dataRoot> --preview
python -m plugin_portal migrate-legacy --source-url http://127.0.0.1:9136/project-delivery-hub --plugin-key company-dev/project-delivery-hub --data-root <dataRoot> --apply
```

迁移范围：

- 5 条旧版 Prompt，保留常用场景、正文和添加时间。
- 鸟瞰全景 4 个 Tab：插件安装、设计交付、代码交付、看板闭环。
- 旧版扩展工具 7 项，转换为当前快照的名称、用途和公开链接。
- 旧版公开 Skills 清单作为研发助手插件本机可见技能白名单，历史迁移壳技能不进入新快照。

不迁移：

- 旧版 28 条工程规范展示投影正文。
- token、cookie、会话信息、绝对路径、运行状态、连接配置或原始异常。
- 其他插件的任何资料。

迁移器先读取并规范化全部来源，再校验目标候选。应用阶段要求目标 Prompt 与流程仍为空或仅包含未保存的默认占位；否则失败并要求用户先处理冲突。扩展工具和技能可见性通过生成新快照应用，不改插件目录。

应用前在数据目录同级的临时受控目录保存当前目标文件副本；全部候选写入临时目录并通过校验后，再逐文件原子替换。失败时保留原数据。迁移回执只记录来源基址、插件身份、数量、内容摘要和时间，不记录令牌、cookie、绝对插件路径或正文。

迁移命令可重复预览；同一来源摘要已成功应用后再次 `--apply` 返回“已迁移”，不重复记录。

## 6. 封面背景来源

`/#/` 保留现有 Start 按钮、转场阶段和 `/#/hub` 目标，只替换背景实现。背景使用 XorDev 发布的 Blackhole shader，并从网络公开来源核对原始表达式与许可；仓库内保留来源、署名、许可和修改说明。

- 许可为 CC BY-NC-SA 4.0，只用于用户已确认的个人非商业 Portal。
- 适配仅补 WebGL 1 输入、输出和本地组件生命周期，不把外部脚本或资源加入运行时。
- 构建后封面不发起远端请求；离线仍能显示背景。
- WebGL 不可用时沿既有本地降级路径显示可操作的 Start，不改变路由与键盘语义。

## 7. Skill 可见性

Portal 核心不硬编码研发助手技能 ID，也不通过描述文字猜测“历史遗留”。迁移器从旧版已审核公开 Skills 清单取得精确 ID，写入 Portal 本机的插件可见性配置；通用插件读取器在生成快照时只对该插件应用此白名单。

没有可见性配置的插件继续展示其全部公开 `SKILL.md`。配置仅影响 Portal 展示，不删除或修改插件文件。

## 8. 安全与错误处理

- 只允许 `http://127.0.0.1` 或 `http://localhost` 来源，拒绝外部主机、用户信息、查询凭证和非 HTTP 协议。
- HTTP 回应设定大小上限、超时和严格 JSON 结构校验。
- Prompt 会话 cookie 只存在于迁移进程内存，不写日志或回执。
- 任何旧版结构漂移、目标资料冲突或候选校验失败均整体停止。
- 迁移不启动、停止或修改旧 Portal 服务。

## 9. 验证

- Python：来源限制、5 条 Prompt、4 个 Tab、分支转换、7 个扩展工具、Skill 白名单、目标冲突、重复应用、失败保留和回执脱敏。
- React：插件站点无切换/管理入口；插件名链接概览；菜单无鸟瞰全景；Prompt 模态框；流程三级级联模态框。
- 静态检查：TypeScript、Vite build、公开仓库路径/凭证扫描。
- 真实浏览器：封面 canvas 就绪且无运行时远端请求；Hub 管理入口保留；进入两个插件均无站内切换；研发助手旧资料可读；昱勝 Inc 资料不受影响；模态框键盘和焦点；刷新路由稳定。
