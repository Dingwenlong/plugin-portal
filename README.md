# Plugin Portal

面向个人与可信局域网使用的多插件门户。Portal 拥有固定页面与独立发布周期，人工纳入插件并生成经过校验的公开资料快照；插件不依赖 Portal，Portal 也不修改或执行插件代码。

当前提供流程、Skills、Prompts、MCP、工程规范及版本沿革六个页面，以及多插件目录、公开快照和按完整插件身份隔离的用户内容。已确认的架构见：

- [多插件只读 Portal 设计](docs/superpowers/specs/2026-08-25-plugin-portal-design.md)

本仓库公开，但个人 Prompts、流程配置、插件路径、插件快照和其他本机资料不得提交。

## 本机运行

需要 Node.js、npm、Python 3.11 或更新版本。先构建，再启动：

```powershell
npm ci
npm run build
.\scripts\start.ps1
```

启动脚本只允许监听 `127.0.0.1:9137`。如果端口已占用会直接停止，不会自动换端口；脚本在独立 GET/HEAD 回读和首页哈希比对通过后才报告就绪。运行资料默认写入 `%LOCALAPPDATA%\plugin-portal\data`，不会写进仓库。

打开 [http://127.0.0.1:9137/](http://127.0.0.1:9137/)。

## 局域网访问模式

本机管理仍只监听 `127.0.0.1:9137`。可信局域网需要跨网段纳入插件、编辑 Prompt、配置流程或发布下载时，可以另启 9135 远程管理模式。它不提供登录验证，也不按来源 IP 做应用层授权；必须只在受控内网和防火墙边界内开放，禁止映射到公网。

远程管理不接收服务器文件路径。纳入插件通过浏览器上传 ZIP，只需选择一次；确认后同时纳入公开资料并发布该 ZIP 的下载。后端只处理当前浏览器会话上传的临时文件，由 Portal 内置校验器检查大小、ZIP 结构、版本、私有资料及文件摘要，再执行发布回读。

```powershell
# 先只读确认现有 Caddy、构建和数据目录，再启动 loopback 后端。
.\scripts\start-remote-management.ps1 -Address <本机局域网IPv4> -CheckOnly
.\scripts\start-remote-management.ps1 -Address <本机局域网IPv4>

# 等价的后端命令；生产环境仍应由脚本完成 PID、哈希和访问模式回读。
python -m plugin_portal serve --remote-management --host 127.0.0.1 --port 9135 --https-origin https://<本机局域网IPv4>:9135 --data-root <资料目录> --web-root <构建目录>
```

- 胶囊与 Hub 的管理按钮在远程管理模式全部开放；目录选择改为浏览器文件选择，不泄露服务端路径。
- 服务只信任精确的 HTTPS Origin 与 Host；跨 Origin 请求、转发头伪造和非预期 Host 均拒绝。
- 启动脚本只启动它自己的 Python loopback 后端，不修改或停止 Caddy，不修改防火墙、系统服务、开机任务，也不操作 9134、9136、9137。
- Caddy 必须继续只监听明确的内网 IPv4、关闭管理端口，并反向代理到 `127.0.0.1:9135`。若现有只读配置含以下写入阻断器，启用远程管理前只移除这两行；其余 TLS、Host 与兜底拒绝规则保留：

```caddyfile
@writes not method GET HEAD
respond @writes 403
```

没有企业证书时可使用 Caddy 内部 CA；访问设备需人工信任公开根证书。CA 私钥只保存在受限的运行目录，不进入仓库、静态目录或共享包。生产切换必须先在非生效端口验证证书链、GET/HEAD、首页哈希、访问模式、上传及回滚路径，再按独立发布授权切换。

### 可选只读模式

只需分享内容时，仍可使用 `--read-only` 或 `scripts/start-lan.ps1`。该模式隐藏纳入、编辑、流程配置与发布入口，并在后端拒绝所有写请求：

```powershell
.\scripts\start-lan.ps1 -Address <本机局域网IPv4> -CheckOnly
.\scripts\start-lan.ps1 -Address <本机局域网IPv4>
```

只读和远程管理是互斥的显式模式；不得同时传入 `--read-only` 与 `--remote-management`。

### 持续启动与发布校验

仓库提供 [持续启动候选与配置说明](scripts/PERSISTENT-LAUNCHER.md)。`scripts/start-persistent.ps1` 默认仅验证候选，不注册任务、不重启线上服务。核心运行文件、Python、Caddy、配置和证书继续严格校验，发布校验器随 Portal 运行目录一起固定摘要。

普通纳入和下载发布使用服务端 `PortalArchiveAuditor`，不运行 Codex CLI，不读取桌面插件安装状态或缓存，也不使用 `PORTAL_AUDIT_CONFIG`。Codex 或 Plugin Inspector 升级、卸载及旧审计配置失效不影响纳入。旧 `auditConfigPath` 字段仍可保留以兼容配置升级，但不读取或传递；历史外部审计适配器仅供显式集成使用，不参与标准服务的发布链路，也不作为失败后的替代通道。

持续启动脚本尚不代表线上计划任务已迁移。正式切换必须先验证候选、可恢复副本和恢复命令，独立进程测试及持久配置回读通过后，才可按发布授权生效。

## 资料边界

每个步骤中的图片按顺序作为独立子步骤，支持标题、说明、前移／后移及删除。原有图片说明继续作为子步骤说明使用，未填写标题时缩略图显示“子步骤 N”，大图查看器显示所属步骤标题。大图的标题、说明和导航合并在底部可隐藏浮层中，编号只在导航中显示；切换子步骤时同步切换对应说明，步骤导航仍切换父步骤。数据沿用图片引用结构，增加可选 `title`（最多 200 字符），原有 `alt` 说明保持兼容（最多 200 字符）；升级不改写既有图片或内容。

流程按保存的步骤顺序展示为连续的纵向编号轴，以连接线和向下箭头标明阅读方向；桌面端并排显示标题与说明，窄屏改为上下排列。编辑时使用上移／下移调整顺序；保存不再要求单一入口、连线或图连通性。历史 `next` 字段保留兼容读取，不控制展示顺序。插件身份、步骤 ID、字段格式、图片归属及修订号冲突检查继续生效。

Hub 中右击插件条目（或聚焦条目后按 Shift+F10）可选择“删除”。确认框展示完整来源与版本，只移除选中的 Portal 目录条目；同名插件的其他来源、插件包、快照和用户内容均保留，重新纳入后可继续使用。只读模式不提供删除入口。

首页 Plugin Family 按插件家族整组排序。拖动条目右侧手柄，或点击手柄／右键选择“上移”“下移”，即可自动保存顺序；其他设备和只读页面也读取相同顺序。同一插件的多个来源一起移动，组内继续优先展示较新版本。已排序后新增家族排在末尾，刷新或升级插件保留其位置。只读模式隐藏排序入口。

`POST /api/plugins/order` 接收完整的 `pluginIds` 家族顺序与 `expectedRevision`，通过原子批次保存目录修订号和独立 `catalog-order` 文档。排序冲突要求刷新后重排；保存结果不明时先回读，不自动重复提交。原有插件身份、快照及用户内容不因排序而改变。

删除接口为 `POST /api/plugins/{完整身份}/remove`，使用现有会话与 `expectedRevision` 检查。列表发生并发变更时须刷新后重新选择；请求结果不明时先回读列表，不自动重试删除。

### MCP 功能与版本记录

MCP 和版本沿革页面的操作栏提供“下载模板”“上传 JSON”，保存后可“导出当前 JSON”。用户下载对应页面模板，让 AI 结合插件资料填写，再上传文件；检查完整内容和增删改预览后，点击“确认替换”整页保存。取消预览不保存。文件上限为 1 MiB，错误会指出对应字段。

MCP 模板按服务列出工具名称、用途及使用场景；版本模板记录版本号、日期、摘要及 added/changed/fixed/removed 变更，未知日期填 `null`。模板中的 `_instructions` 只用于生成指导，不保存。所有内容以纯文本展示。

页面文档通过 `/api/plugins/{完整身份}/content/{mcp|releases}` 读取，`/template` 与 `/export` 下载，`POST /preview` 校验候选，`POST /confirm` 按候选及修订号保存；写入沿用 Portal 会话和访问模式。只读模式允许阅读与下载，禁止上传。说明保存在数据目录的 `mcp-documents.json`、`releases-documents.json`，插件重新纳入不会覆盖；MCP 说明版本与当前插件不一致时会显示两者。顶部下载始终对应实际插件包。

Header 仅保留插件标识、导航、版本下载与全局外观。编辑流程、新增 Prompt、文档下载和上传位于页面内容区；流程 Tab 与编辑入口排列在同一操作区，进出编辑时保留当前 Tab 和步骤位置。Prompt 列表保留输入中的换行。扩展工具页已移除，旧链接跳转同插件 MCP 页，历史快照字段继续兼容。

### 插件资料与用户内容

- 插件必须由用户人工纳入或人工刷新，不做目录扫描和在线状态推断。
- 浏览器只读取 Portal 已提升的不可变公开快照，不直接访问插件目录。
- Skills 只显示公开名称与说明；MCP 默认只显示服务 ID，也可读取插件提供的可选 `.mcp.public.json`，展示名称、用途、能力和是否包含写入操作；不会保存 command、args、env 或凭证。
- 工程规范只读取用户批准的插件内相对 Markdown 路径，并在 Portal 内以纯文本安全渲染。
- Prompts 与鸟瞰全景流程归 Portal 用户所有，按完整插件身份隔离。
- 插件导入候选、个人 Prompts、流程和服务日志只位于本机数据目录。

插件需要补充 MCP 公开说明时，可在插件根目录加入：

```json
{
  "mcpServers": {
    "vmp-mcp": {
      "name": "VMP 工单服务",
      "purpose": "查询问题单、分析记录与关联待办。",
      "capabilities": ["查询问题资料", "读取关联待办", "更新处理状态"],
      "writeEnabled": true
    }
  }
}
```

文件中的服务 ID 必须已存在于 `.mcp.json`。Portal 只导入上述封闭字段；文件缺失或某个服务没有对应说明时，该服务继续只显示 ID。

根地址 `/#/` 直接展示插件列表，与 `/#/club` 共用同一页面，保留各自地址。点击 Plugin Family 旁的加号即可纳入或重新纳入插件。旧 `/#/hub` 自动替换为 `/#/club`，不额外增加浏览器历史记录。插件站点只显示当前插件内容。远程管理使用浏览器 ZIP 上传；本机目录选择模式打开 Windows 目录窗口，并从插件清单自动识别名称、ID 与版本。所有变更仍经过会话令牌与 revision 门禁。

包含 `.agents/plugins/marketplace.json` 的发行包会自动识别并锁定来源市场，预览与发布使用同一身份。普通插件 ZIP 未声明市场时，来源市场可在高级区域修改。同一来源纳入不同版本时，确认前显示当前版本与将切换的版本；允许旧版本，用户内容仍按完整插件身份保存。

高级区域的“公开工程规范”提供 Markdown 文件列表，可按标题或文件名搜索、勾选并预览正文。只有更新预览并确认纳入后，所选正文才写入公开快照；取消不保存。文件列表最多 1024 项，读取总量为 8 MiB，单文件沿用现有上限；不遍历链接、依赖或缓存目录。不能通过现有公开文本校验的文件会标明原因且不能勾选。预览正文与选择都绑定当前会话和冻结候选，选择变化会生成新候选，旧确认随即失效。

导入预览返回 `importOptions`，包含市场、当前版本、目录修订号与规范文件选项。`POST /api/plugins/import/candidates/{candidateId}/rules/read` 读取指定正文，`rules/preview` 根据所选路径生成新预览；两者复用现有会话、同源及只读权限检查。

纳入或刷新成功后，Hub 目录会立即重读；插件图标 URL 同步绑定新的目录修订号，因此既有条目也会重新读取图标，无需手动刷新页面。

## 发布下载包

Hub 不再提供需要二次上传的“发布下载”按钮。Portal 只分发现成候选，不替插件生成 ZIP：

1. 按目标插件自身的发布流程生成候选 ZIP。
2. 点击 Hub 加号，选择一次 ZIP，检查自动生成的公开资料预览。浏览器不提交本机绝对路径。
3. 点击“确认纳入”。Portal 服务端检查同一 ZIP 的结构、身份、严格 SemVer、清单资源、私有文件与常见凭证特征，并计算完整文件摘要，再原子发布为 `<pluginId>-<version>-<target>.zip`，从下载服务回读核验字节后更新活动快照与目录。
4. 列表和插件图标自动刷新，进入插件页即可下载，不需要再次上传。通过本机目录纳入仅生成公开资料；需要下载时，使用远程管理入口重新纳入正式 ZIP。

下载目录沿用现有 `%LOCALAPPDATA%\project-delivery-hub-share\downloads`，必须事先存在并由现有 9134 服务读取；Portal 不创建、配置或重启 9134。候选上限为 128 MiB。同版本同文件可核对后复用，同版本不同 ZIP 绝不覆盖。确认前候选变化、服务端校验拒绝、写入失败或下载回读不一致都会停止；已激活但回读失败的新文件会被隔离，既有下载不受影响。发布回执位于 Portal 私有数据目录，记录校验器名称 `portal-archive`、版本和文件摘要，不记录候选绝对路径或原始命令输出。

### 规范核心 ZIP

正式规范导入对象是原始单插件核心 ZIP，采用 Plugin Inspector 维护的 `codex-plugin-portal` v1 文件组：核心 ZIP 使用唯一的 `<plugin-id>/` 顶层目录，`plugin-package.json`、检查回执和运行时、数据、签名等附属资产放在 ZIP 外。规范与机器结构分别以 Inspector 的 `references/portal-package-v1.md` 和 `schemas/portal-package-v1.schema.json` 为准，Portal 不另建一份格式标准。

Portal 仍只上传并分发同一个核心 ZIP，不需要第二次上传或再套一层 ZIP。元数据是支持该规范的 Inspector 的外置发布检查输入；Portal 当前既不自动读取它，也未实现 sidecar 与纳入目标 `target` 的自动冲突校验。纳入时应按发布者回执核对来源市场，在高级选项中勾选已批准的公开工程规范；未选择时缺省为空。扩展工具字段仅保留旧包兼容，不再提供配置入口。检查回执不能代替实际公开预览。

公开资料继续从被检查的核心生成。Portal 不读取、下载或执行 ZIP 外的附属资产，也不把文件摘要匹配当成签名可信、安装成功或正式发布通过。原始 ZIP SHA、核心文件集 SHA 与 Portal 的 `provenance.packageDigest`（公开投影摘要）是三种不同的摘要，不得互换。核心文件集采用插件根目录相对路径与逐文件 SHA 的规范 JSON 摘要，与 Inspector 的表示保持一致；发布者仍可独立使用 Inspector 检查外置元数据。

### 完整市场发行包兼容

此兼容分支不属于 `codex-plugin-portal` v1 规范；正式规范发行仍应提供上述单插件核心 ZIP。

除原有插件根目录 ZIP 和单层包装 ZIP，浏览器纳入也支持只包含一个插件的完整市场发行包。Portal 读取包内唯一的 `.agents/plugins/marketplace.json`，按本地 `source.path` 定位 `.codex-plugin/plugin.json`；例如 `marketplace/.agents/plugins/marketplace.json` 中的 `./p` 指向 `marketplace/p`。目录名不固定，但路径必须以 `./` 开头、不得越界，目录和清单身份必须一致。多插件包、远端 Git 引用、缺失清单、路径冲突及不安全条目仍拒绝。仅含运行时或数据的 ZIP 不是插件发行包。包内市场作为纳入目标并在预览中锁定；未声明市场的普通插件 ZIP 使用用户在高级选项中选择的来源市场。

预览只解压插件子树，不解压或执行安装器、运行时及数据附件。外层条目上限仍为 4096、展开总大小仍为 256 MiB、普通文件仍为 32 MiB；完整发行包中与 `marketplace/` 同级的 `release-assets/` 内直接存放的有效 ZIP 附件可达 128 MiB，作为不展开的附件处理。整个上传 ZIP 的 128 MiB 上限不变。

服务端直接校验原始 ZIP 的冻结副本，市场名称必须与所选目标一致。校验覆盖市场配置、插件子树及其他每个外层文件，完整发行包的文件集摘要使用原包路径；嵌套 ZIP 只按不展开的字节检查，不宣称完成递归扫描或发行者签名验证。校验失败即停止，发布与回读始终使用用户上传的原 ZIP，临时副本在成功或失败后均清理。历史外部工具适配器仍保留临时视图兼容实现，标准服务不调用它。

### 规范核心 ZIP

正式规范导入对象是原始单插件核心 ZIP，采用 Plugin Inspector 维护的 `codex-plugin-portal` v1 文件组：核心 ZIP 使用唯一的 `<plugin-id>/` 顶层目录，`plugin-package.json`、检查回执和运行时、数据、签名等附属资产放在 ZIP 外。规范与机器结构分别以 Inspector 的 `references/portal-package-v1.md` 和 `schemas/portal-package-v1.schema.json` 为准，Portal 不另建一份格式标准。

Portal 仍只上传并分发同一个核心 ZIP，不需要第二次上传或再套一层 ZIP。元数据是支持该规范的 Inspector 的外置发布检查输入；Portal 当前既不自动读取它，也未实现 sidecar 与用户所选 `target` 的自动冲突校验。纳入时应按发布者回执明确填写该版本的 `target`，把已批准的 `portal.approvedRulePaths` 与 `portal.extensionTools` 填入现有高级选项，缺省为空。检查回执不能代替实际公开预览。

公开资料继续从被检查的核心生成。Portal 不读取、下载或执行 ZIP 外的附属资产，也不把文件摘要匹配当成签名可信、安装成功或正式发布通过。原始 ZIP SHA、Inspector 文件集 SHA 与 Portal 的 `provenance.packageDigest`（公开投影摘要）是三种不同的摘要，不得互换。使用新的 Inspector 规范检查入口前，仍须显式验证工具版本、路径和摘要；不自动升级现有固定审计工具。

如果 IIS 的 9134 返回 502.3，应先检查其配置中的本机上游是否监听，而不是重新上传 ZIP。仓库提供独立的[下载后端恢复入口](scripts/DOWNLOAD-SERVICE.md)，只服务既有公开文件，不依赖旧 Prompts 后端或插件缓存；它必须经单独授权和两阶段验证后启用，不由 Portal 自动启动。

只读模式不显示纳入入口，并在读取或解析候选前拒绝写请求。下载按钮区分检查中、可下载、未提供和检查失败；只有下载服务明确返回文件不存在时才显示未提供，临时故障可重新检查。

## 读取、保存与异常恢复

- 目录、快照、Prompts、流程和下载检查分别加载。单项读取失败不影响其他页面；只重试失败资源，已有列表在刷新失败后继续显示。
- 读取请求 15 秒超时；普通保存 30 秒；ZIP 上传、预览和确认各 300 秒。原生目录选择没有这些网络短超时。切换插件时取消旧读取，迟到响应不能覆盖当前内容。
- 纳入阶段依次显示上传、生成预览、校验并纳入、刷新列表。收到成功回执后若列表刷新失败，显示“已纳入，列表刷新失败”，只重试刷新，不重复纳入。
- 写入超时、断线或回执无法识别时显示“结果待确认”，保留本次冻结内容，先读取活动快照、下载信息或已保存文档核对。无法确认时不自动重发；可继续核对，或明确关闭并退出恢复界面。
- 服务重启造成 `invalid_session` 时，普通保存仅重建会话并携原修订号重试一次。上传候选失效后保留本标签页所选文件，重新生成预览，再由用户确认。
- 保存期间锁定相关编辑与关闭操作。修订冲突保留草稿，支持复制草稿、查看最新内容；载入新基准或替换流程草稿必须另行确认。
- 弹窗进入、Tab 循环和关闭焦点归还统一处理；未保存内容关闭或站内跳转前确认，保存中禁止误关闭。浏览器强制结束或关闭标签页不提供后台续跑；草稿和所选文件仅保留在当前页面内存中。

## Overview 就地编辑

点击“编辑流程”后，Overview 直接进入编辑模式，不再打开整页配置弹窗。当前 Tab 与可见步骤位置保持，点击步骤或区域标题可切换右侧属性栏；修改立即显示在画布中，但只在“保存流程”成功后公开。

桌面属性栏随页面滚动保持可用；窄屏先显示流程，点击步骤进入单步编辑，底部“返回流程”回到原步骤并保留草稿。底部固定显示保存状态、保存与退出操作。新增 Tab、区域、步骤及上移/下移沿用原有方式，本轮不引入拖动排序或自动保存。

退出或切换页面前会确认未保存内容；保存中锁定编辑与退出，保存结果待确认时可继续核对，或明确退出并稍后核对。普通页面键盘焦点不被属性栏约束，只有退出确认和图片查看弹窗保留焦点循环。

## Overview 步骤图片

在插件 Overview 点击“编辑流程”，选择步骤后，在属性栏选择图片，也可将图片拖入图片区域或在该区域粘贴截图。每步骤最多 6 张，支持静态 PNG、JPEG、WebP；单张原文件最多 10 MiB、2000 万像素。可以修改图片说明、前移、后移或删除，所有上传完成后再保存流程。Overview 在说明下方以双列完整缩略图展示，点击可放大，左右方向键切换、Escape 关闭。

- 上传仅暂存；只有保存流程引用的图片才能公开读取。取消编辑不会修改已保存内容。上传失败保留本标签页内的原文件与文字草稿，支持逐张重试或删除；关闭编辑器会释放本地预览并取消未完成请求。
- 图片引用与顺序参与现有修订冲突和保存结果核对；写入结果待确认时不会重发。暂存过期导致保存被拒绝时，仍可使用保留的本地文件“重新上传”。刷新或关闭整个浏览器页面会丢弃尚未保存的内存草稿。
- 图片按完整插件身份存入 Portal 数据目录下的 `workflow-images/`，索引为 `workflow-images.json`；`workflows.json` 只保存 `images: [{assetId, alt}]`，旧步骤没有此字段也可读取。图片不会写回插件目录、安装包或仓库。备份时应在停止写入后，将流程、图片索引和图片目录一起备份；仍只支持单个管理服务写同一数据目录。
- 后端实际解码、校正方向、移除附带元数据并重新编码，生成最长边 320px 的缩略图。归一化高清图另设 40 MiB 上限；最多同时处理 2 张，未引用暂存总容量最多 256 MiB。SVG、动图、损坏文件、格式伪装和跨插件图片引用均被拒绝。
- 未引用图片至少保留 24 小时，之后在下一次上传或保存流程前清理；没有写入操作时不会唤醒后台任务。删除前在同一个存储锁内重读已保存引用，仍被任何步骤使用的图片不会清理。删除图片或步骤仅在保存成功后改变公开可见性。
- 只读模式可查看已保存图片，但不能上传。图片接口沿用原有 Host、同源及会话校验，不放宽局域网安全边界。

图片处理是可选运行依赖，精确锁定在 `requirements-images.txt`。需在**启动 Portal 的同一 Python 环境**中安装；生产安装、重启仍需单独授权并先验证候选：

```powershell
python -m pip install -r requirements-images.txt
python -c "import PIL; assert PIL.__version__ == '12.3.0'"
```

缺失或版本不匹配时，仅上传返回 `image_processing_unavailable`；普通页面读取、无图片流程编辑以及已保存图片读取不依赖 Pillow。
